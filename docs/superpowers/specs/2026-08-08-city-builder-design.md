## 1. 项目概述

一款网页版城市/基地建设经营游戏。核心玩法:**养活自己世界的人民**,从最初的部落时代逐步发展到世界帝国。玩家通过建造建筑、生产和获取各种资源(尤其是粮食)让人口生存、增长,并逐个时代进阶。

- 先做网页版 + PWA,后期用 Capacitor 打包上架 Google Play / App Store
- 账号 + 服务器存档,换设备不丢进度
- 玩家互动:排行榜、参观好友城市、交易市场(无战斗)
- 商业化:内购(付费货币钻石 + 加速),架构从第一天预留
- 画面:2.5D 等距视角,先用免费素材包(Kenney 等 CC0),支持后期换皮升级美术

## 2. 总体架构

```
浏览器 / PWA / (后期 Capacitor 壳)
        │
   前端 SPA(纯静态文件:HTML + JS + 素材)
   - PixiJS 做 2.5D 等距渲染(已批准,单文件引入,不用 npm/构建工具)
   - 只负责展示和操作,不计算任何数值
        │  HTTPS JSON API
        ▼
   PHP 8.3 纯 API(无框架,PDO 具名占位符,EMULATE_PREPARES=true)
   - 所有游戏数值在服务端计算(防作弊)
   - 资源产出/消耗:时间戳懒计算,无 cron、无常驻进程
        ▼
   MariaDB(utf8mb4,表名字段名 snake_case)
```

关键决策:

- **前后端完全分离**:前端是纯静态文件,后期上架商店时用 Capacitor 打包同一套前端,API 不变。
- **Token 认证**(不用 PHP session cookie):登录后发放随机 token,前端存 localStorage,每次请求带 `Authorization` 头。原因:Capacitor 壳内 cookie 不可靠,token 方式网页/app 通用。
- **部署**:cPanel 上传,`config/env.php` 切 test/prod,单一代码库。
- **时区**:`Asia/Kuala_Lumpur`;数据库时间统一存 UTC 时间戳,显示时转换。

## 3. 数据驱动的内容架构(重要)

**游戏内容(时代路线、资源种类、建筑及数值)由用户定义,代码不写死任何具体内容。**

- 所有内容存数据库配置表:
  - `era` 时代表:排序、名称、进阶条件
  - `resource` 资源表:名称、类别(食物/材料/货币)、解锁时代
  - `building` 建筑表:名称、解锁时代、占地、功能类型(生产/储存/民居/装饰等)
  - `building_level` 建筑等级表:每级产量、容量、升级费用、升级耗时、人口占用等
- 工作流程:Claude 提供**填表模板**(Excel,带部落时代示例数据和字段中文说明)→ 用户填写 → 讨论定稿 → 写导入脚本入库。
- 以后加新时代 = 加数据,不改代码。后期计划做后台管理界面在线编辑(本期不做)。

## 4. 核心玩法系统

### 4.1 地图与建筑

- 每个玩家一块等距格子地图(初版 24×24),初始解锁中心区域,随发展扩张。
- 建筑可建造、升级、移动;数值全部来自 `building_level` 配置表。
- 建造/升级有耗时,记 `finish_at`,到点后玩家请求确认,服务端校验时间通过才生效。

### 4.2 生存循环(核心)

- **人口**由民居类建筑提供上限;人口是建造/生产的前提。
- **人口消耗食物**:服务端按时间结算(懒计算)。食物富余 → 人口增长、产出正常;食物断供 → 产出下降、人口流失。具体数值(消耗率、增长率、惩罚曲线)由用户在模板中定义。
- **资源获取**:生产建筑按时间产出,玩家收取时结算 `min(时长 × 产量, 容量上限)`;后续版本可扩展采集、任务等更多获取方式。

### 4.3 时代进阶

- 时代是纯数据(`era` 表)。满足进阶条件(指定建筑等级、资源量等,条件由用户在模板中定义)后可进阶。
- 进阶解锁新建筑、新资源。时代路线由用户填表决定(示例占位:部落 → 青铜 → …… → 世界帝国)。
- 第一版内容量:**前 2-3 个时代**,先把生存循环和进阶机制跑通。

### 4.4 经济与双货币(为内购预留)

- **普通资源**(粮食、材料等,种类由用户定义):游戏内产出,用于建造升级。
- **钻石**(付费货币):现阶段通过任务/成就少量发放,后期接支付充值;用途:加速倒计时、稀有装饰。
- 钻石发放/消费全部走服务端流水表 `diamond_log`,从第一天可审计;接支付时不改架构。

### 4.5 新手引导 + 每日任务(简单版)

- 首次进入引导建 2-3 栋建筑,理解「生产 → 喂人口 → 发展」循环。
- 每日任务发少量钻石和资源,拉留存。

## 5. 玩家互动

- **排行榜**:按时代 + 繁荣度(具体口径随数值表定)排名,分页查询。
- **参观好友城市**:只读拉取对方城市布局渲染,不能操作。
- **交易市场**:玩家挂单卖资源(定价出售),其他玩家购买,服务端撮合,收手续费做经济回收。防刷:挂单数量上限、价格区间限制(具体数值后定)。

## 6. 安全与防作弊

- 所有数值服务端结算,前端只做展示和倒计时动画。
- Token 认证(随机 64 位 hex,数据库存 hash),bcrypt 密码哈希,敏感数据 AES-256-CBC + HMAC-SHA256。
- 写操作校验 token + 请求限流(按用户/按 IP 简单计数)。
- 时间校验:所有倒计时以服务端时间为准,客户端时间仅显示用。
- 错误写日志文件(时间、错误、上下文),prod 不显示错误详情,`APP_DEBUG` 控制。

## 7. 错误处理

- API 统一 JSON 响应格式:`{ok: true, data: ...}` / `{ok: false, error_code: ..., message: ...}`。
- PDO/程序错误写错误日志;用户只看到友好提示。
- 前端对网络失败做重试提示,不做本地补偿计算(数值以服务端为准)。

## 8. 测试

- 核心逻辑(资源结算、食物消耗、人口增减、进阶校验、市场撮合)写 PHP 单元测试:简单断言脚本(不用框架),`php tests/run.php` 一键跑。
- 交付前所有 PHP 文件过 `php -l`。
- 前端手动测试 + 浏览器自动化(Chrome DevTools)验证关键流程。
