# W14 后台定义新增/分类/联动波(需求定稿)

> 用户 2026-08-13 提出。前置:W13 落地(玩家详情全景页 + 等级无上限/Excel)。
> 结论先行:四张定义表字段均已齐备,**本波不需要任何表结构变更**。

## 需求清单(用户原话拆解)

1. **建筑等级手动增加**
   - 建筑等级面板加「新增等级」:选建筑 → 预填该建筑当前最高级数值的副本 → 改完提交。
   - 服务端:INSERT 到 building_level_definition,强制 level = 当前最高级 + 1(等级连续性与 W13-2 导入同一不变量),字段校验复用现行 FIELD_MAX 管线,GDV bump + ADMIN_CONFIG_CHANGE 审计。

2. **科技分类 + 手动增加**
   - technology_definition 已有 `branch` 列(治理/科研/商贸、国防、工业/加工、仓储/运输、生存/农业),后台科技面板此前未显示——按 branch 分组/筛选展示。
   - 「新增科技」:tech_id / name / era_key / branch / knowledge_cost / research_minutes / prerequisite_tech_ids / unlock_building_ids 全量表单;前置科技与解锁建筑要校验 ID 存在;tech_id 唯一。

3. **NPC 定义可改可增**
   - 修改:现有 editNpc 只开放少数列且 FIELD_MAX 裸奔(旧挂账)——把可编辑列扩到全表(name_zh/category/min_era/技能四件/工资口粮/rarity/recruit_source/文案两列/trait_json/trait_multiplier),逐列 FIELD_MAX。
   - 新增:全字段表单,npc_id 唯一,trait_json 合法性校验。

4. **市场定义可增可改**
   - 修改:editMarketDefinition 现状核对,可编辑列扩全(trade_mode/base_price/min_price/max_price/volatility/elasticity/fee_rate/base_liquidity/note)。
   - 新增:resource_id 必须已存在于 resource_definition(不准借道发明新资源),唯一约束;价格三元组 min ≤ base ≤ max 跨字段校验。

5. **玩家详情 → 资源补偿联动**
   - W13-1 的玩家详情页里,资源现况每行可点击 → 跳补偿面板,并自动预填:username/city_id/该资源。
   - 实现建议:hash 参数(#compensation?city=21&resource=wood)或 sessionStorage 预填,由补偿面板在挂载时消费;别破坏现有 tab 路由。

## 通用纪律
- 新增走与编辑同一 11 步管线(allowlist → 校验 → 强制 reason → 事务 → 审计 create → GDV bump → 缓存 flush)。
- ID 格式校验(与现有 ID 风格一致)、唯一性、外键存在性,全部 Fail Closed。
- 新增/修改均不删数据;删除不在本波范围。
- 无迁移、无 GDV 结构位变更(数据位照常 bump)。
